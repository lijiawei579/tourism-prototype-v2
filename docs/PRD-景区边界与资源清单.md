# V2补充PRD：景区边界与资源清单

版本：1.3（V2.16度分秒与统一坐标录入）  
日期：2026年11月10日  
适用：旅游景区质量等级申创（4A级）  
交付状态：前端演示已实现。坐标校验、地图确认、空间筛选、清单增删改、重生成差异、草稿保存、资源材料版本冻结与只读查看均已加入V2；不改变现有审批链路、评分标准和AI禁用范围。真实GIS、主库服务、服务端鉴权及不可变存储仍待集成，不冒充生产能力。

实现说明：地图采用动态离线经纬度底图，不提供真实道路或影像；默认三行演示坐标，可零输入体验全部主流程。资源名称及备注取自所附资源一览表，空间坐标为独立演示分布，不代表实测位置。主类采用八类展示，下级分类保留所附样表原口径，分类映射尚待正式核定；F—H三级字典未提供，当前展示0项并禁用相应补录分类，不臆造标准编码。原子保存、revision冲突和历史快照在浏览器本地实现，正式后端仍应按下列接口契约再校验。

## 1. 目标与范围

市州申创人员在第三部分“旅游景区申请报告—旅游资源概述”中填写景区边界，经地图确认后查询该边界关联的在库旅游资源，再按主类筛选形成项目资源清单，供申报与评审核验。

资源概述文字和原有申报范围附件保留。边界填写及资源清单统一在第三个Tab“景区申请报告”的“景区旅游资源概述”中展示，清单紧随边界区域；第二个Tab只保留基本数据和原范围附件。不把资源查询设为新的审批节点。

本功能使用坐标校验、空间查询和分类筛选，不依赖AI，不自动打分，不承诺发现尚未入库的资源。查询结果为空不等于景区不存在资源。

### 1.1 功能拆解

| 功能项 | 一级功能 | 二级功能 | 功能描述 |
|---|---|---|---|
| 景区申报 | 资源概述 | 输入边界坐标 | 默认3行，每行一个经度、一个纬度，支持增删行，按输入顺序构成边界。 |
| 景区申报 | 边界确认 | 生成及核验边界 | 校验坐标后打开地图弹窗，显示闭合边界，取消返回修改，确认后查询资源。 |
| 景区申报 | 资源查询 | 在库资源查询 | 按已确认边界查询当前账号有权用于申报的在库资源，保留来源与版本。 |
| 景区申报 | 资源筛选 | 主类多选 | 按GB/T 18972的主类多选，显示各类命中数，筛选查询结果。 |
| 景区申报 | 资源清单 | 生成清单 | 确认后在第三个Tab资源概述中生成五列、固定高度、可纵向滚动的清单。 |

## 2. 页面位置与主流程

合并后的填报步骤：基本信息与景区简况 → 景区基本数据 → 景区申请报告 → 附件与提交。

1. 第三部分“景区旅游资源概述”正文下展示“景区边界”坐标区，默认三行演示坐标，分别标为边界点1、2、3；每行只有经度和纬度两个输入框，另有行操作。默认值不代表真实申报范围，正式版应按年度填报规则决定是否留空。
2. 用户依次填写边界点，可“添加边界点”，也可删除多余行；保留至少三行。
3. 点击“生成边界”，先校验，成功后打开同一个两步弹窗：第一步“确认景区边界”，第二步“选择资源主类”。不叠加多层弹窗。
4. 地图显示闭合边界和编号顶点，自动缩放到完整范围。用户可缩放、平移查看；本期规划不增加地图拖点编辑、自动纠偏或文件识别等额外功能。
5. 第一页点击“返回修改”或关闭弹窗，返回第三部分，保留输入但不覆盖已确认边界和清单；点击“确认边界，查看资源”后进入第二页并查询。
6. 第二页显示在库资源命中总数、主类多选、各类数量及资源预览，可全选/清空，查询结果应完整可遍历，不因预览分页而丢失资源。
7. 点击“生成资源清单”，成功后关闭弹窗，停留在第三个Tab并滚动定位到边界下方的资源清单，提示生成条数；不切换Tab，坐标及资源概述正文不丢失。
8. 用户维护清单后可继续填报或暂存；正式提交仍走已有完整性校验、真实性确认和提交流程。

第三部分同页显示已确认边界状态、边界点数、清单条数、“查看已确认边界”“生成边界”及“资源清单”；清单中的“修改边界”仅滚动定位到同页上方边界，不切换Tab。相关入口已加入当前V2；再次点击生成执行重新生成差异核对。

## 3. 坐标输入与校验

| 项目 | 规则与错误反馈 |
|---|---|
| 输入格式 | 默认度分秒分栏录入，可切换十进制度。经度在前、纬度在后；度、分为非负整数，秒最多6位小数，分、秒均小于60，经度上限180、纬度上限90且上限处不得有非零分秒；方向选择东/西经和南/北纬。不自动交换两者。十进制度最多8位小数，保留原输入，显示精度不代表测量精度。 |
| 有效范围 | 经度−180至180，纬度−90至90；拒绝非数值、NaN、无穷值、粘贴多个坐标到一个框等情况。 |
| 最少顶点 | 至少3个不同顶点；默认3行均需完整填写。新增且完全空白的末尾行可忽略，半填行必须补齐或删除。 |
| 点序与闭合 | 按边界连续顺序输入，不自动按经纬度排序。系统连接末点与首点；用户重复输入首点作为末点时先去掉重复闭合点，再验证至少3个有效顶点。 |
| 重复/退化 | 拒绝其他重复点、相邻重合点、三点共线或零面积边界；标注问题行。 |
| 自交 | 拒绝蝴蝶形等自相交多边形，提示调整边界点顺序。 |
| 异常定位 | 在对应行显示原因，聚焦第一处错误，不清空其他坐标；不打开空地图。 |
| 空间能力范围 | 首版仅单个闭合多边形；多面、飞地、内洞等复杂边界另行评估，不擅自简化真实申报边界。 |
| 技术边界 | 前后端均校验，服务端不得信任仅前端生成的几何；超出GIS引擎容量时明确提示，不静默截断顶点。容量上限在GIS选型后确认。 |

默认填报标准为CGCS2000（EPSG:4490），可选WGS84、GCJ-02、BD-09；边界点、申报资源新增/编辑弹窗和保留的通用经纬度字段同步支持。系统统一转为CGCS2000后预览、查询和保存，同时保留来源标准和原始输入。切换标准不改变输入值，重新编辑恢复原始输入，避免重复转换。原型中非CGCS2000来源采用近似转换并显式标记，精确测绘成果需接入正式转换参数；细节见[坐标标准与自动转换PRD](PRD-坐标标准与自动转换.md)。

现有“申报详细范围与面积”文字和任意格式范围附件不自动解析、不替换；边界不一致时供人工核验，不擅自改写申报面积。

## 4. 地图确认与资源查询

### 4.1 弹窗第一步：确认景区边界

- 标题：确认景区边界；副标题显示项目名称、坐标系和有效顶点数量。
- 地图：边界半透明填充、轮廓清晰、顶点编号可辨认；放大缩小不修改坐标。
- 操作：“返回修改”“确认边界，查看资源”。确认按钮仅在几何校验通过、地图加载成功时可用。
- 地图失败：展示原因和“重试”，保留输入，允许返回；不能用静态假图替代真实边界。
- 关闭或Esc等同取消；不生成资源清单，不覆盖已有正式材料版本。

### 4.2 弹窗第二步：选择资源主类

进入即按确认的边界查询，不要求用户逐个录入资源名。查询成功后显示“在库匹配N项”；分类过滤是在这次匹配集合中进行，不是查询全库任意资源。

拟采用GB/T 18972—2017《旅游资源分类、调查与评价》的八个主类，版本需厅方与资源主库维护方确认后冻结；不混用2003版同名/异名类别：

| 代码 | 主类 |
|---|---|
| A | 地文景观 |
| B | 水域景观 |
| C | 生物景观 |
| D | 天象与气候景观 |
| E | 建筑与设施 |
| F | 历史遗迹 |
| G | 旅游购物品 |
| H | 人文活动 |

- 使用多选框，默认选中有命中的全部主类，零命中类别置灰但保留名称和0项。
- 同时显示各类命中数和当前选中资源数，支持“全选有结果类别”“清空选择”。未选任何类别时不允许“生成资源清单”，避免把误操作当成清空已有清单。
- 亚类和基本类读取主库中与标准版本一致的三级字典；前端不臆造分类，不使用自由文本替代分类编码。
- 数据加载中显示进度态并禁用重复提交；失败显示“查询失败，请重试”，不把失败显示为“0项”。
- 无命中时明确“当前边界内暂无可查询的在库资源，可返回核对边界，或在当前Tab手工维护本次申报清单”。如用户继续，应单独确认“生成空清单”后定位同页清单，不伪造资源。
- 有资源缺少分类时单列“分类待核对”的数据质量提示和数量，可返回或在空/不完整清单确认提示后继续；不擅自归入某个主类。主库需补齐分类，申报清单可人工更正副本。
- 第二步可“返回边界预览”或“取消”；返回保持本次选择，取消不修改原清单。

### 4.3 空间命中口径

仅查询有效、可用于本次申报的在库资源，按稳定资源ID去重，不按资源名称去重。点资源以位于多边形内部或边界上为命中；线、面资源以与边界相交为候选，部分相交须在备注标注“部分位于申报边界内，待核对”，不得声称整个资源均在景区内。无坐标、无法转换或无几何数据的资源不能自动判定在边界内，返回可识别的数据质量提示，不展示为完整空间匹配。

查询结果记录主库版本/更新时间、边界版本和查询时间，避免后续主库变化悄悄改写已提交材料。只把账号授权可用于申报的资源带出，不因空间命中泄露受限资源信息。具体有效状态、共享范围和线面跨界口径需与资源平台确认后纳入接口契约。

## 5. 第三个Tab资源清单

### 5.1 展示

清单位于第三个Tab“景区申请报告”的“景区旅游资源概述”内、边界填写区之后，标题为“景区资源清单”，显示总条数、分类版本、生成时间及“草稿/已提交只读”状态。正文表格严格五列：

| 主类 | 亚类 | 基本类 | 资源名称 | 备注 |
|---|---|---|---|---|
| 读取分类名称 | 读取分类名称 | 读取分类名称 | 读取资源名称 | 系统提示及申报说明 |

表格建议高度约320px、表头固定，超出部分在区域内纵向滚动，不把页面无限拉长；长备注折行或展开查看，不隐藏完整内容。大数据量可虚拟滚动或分段加载，但计数为完整结果，保存不能只保存可视行。

不增加第六个“操作”数据列：可编辑状态下点击行选中，在表格上方提供“新增资源”“编辑所选”“删除所选”；未选行时后两项禁用。只读状态隐藏维护按钮。

### 5.2 新增

点击“新增资源”打开编辑弹窗，依次选择主类、亚类、基本类，输入资源名称及可选备注。优先从已命中但未纳入的在库资源中选择，也允许补录本次申报所需的资源；手工补录标记来源为“申报补录”，不自动创建资源主库记录，也不伪装为空间命中结果。

分类与名称必填，备注选填；分类逐级联动，父级改变后清空不兼容的下级。相同主库资源ID不得重复添加；同名不同ID允许存在，并提醒核对位置或分类。手工同名同基本类时提示可能重复，由用户确认，不直接删除真实不同资源。

### 5.3 编辑

点击“编辑所选”打开五项内容；保存前校验三级分类隶属关系、名称非空、输入长度与接口契约一致。编辑只改申报副本，保留原resourceId、原始分类/名称快照和修改标识，以便审核核对。系统跨界提示作为只读来源提示保留，用户可另写备注，不能删除系统事实来掩盖位置问题。

### 5.4 删除

选择行点击“删除所选”，二次确认显示资源名称；取消不改变数据，确认只从本次申报清单移除，不删除主库资源。清空最后一项时明确提示“本次申报资源清单将为空”。

### 5.5 重新生成与草稿保存

- 坐标或分类选择改变后，已有清单标记“边界/筛选已变化，清单待更新”，不能仍显示为匹配新边界的结果。
- 点击重新生成不会立即覆盖旧清单；查询成功后给出新增、保留、移出条数及手工修改影响，再由用户确认替换。
- 按resourceId保留仍命中的人工修改与备注；不再命中的原记录和手工补录项需让用户选择保留为“人工保留，待核对”或移除，不能静默丢弃。
- 取消查询或替换时保留原清单和确认状态；尚未确认的新坐标作为草稿保留，明确“有未确认修改”。提供“放弃本次边界修改”恢复已确认版本。
- 确认替换是坐标、查询版本和清单的一次原子保存；失败保持旧数据可用，可重试，不出现新边界配旧清单的假成功。
- 沿用暂存草稿和重新登录续填。资料补正可以更新本次草稿，提交时形成新的材料版本，既有专家意见和历史正式材料不覆盖。

## 6. 状态、提交与评审

| 状态 | 页面提示 | 可用操作 |
|---|---|---|
| 未填写/坐标未完整 | 尚未确认边界 | 编辑坐标；无有效边界不能查询 |
| 校验通过、预览中 | 请确认边界范围 | 返回修改、确认并查询 |
| 查询中 | 正在查询在库资源 | 取消；不能重复生成 |
| 查询成功、未生成 | 匹配数量及主类勾选 | 筛选、返回、生成清单 |
| 已生成且一致 | 已生成N项，显示版本时间 | 维护清单、查看边界、重新生成 |
| 边界/筛选变更 | 清单待更新 | 重新查询并确认，或放弃修改恢复一致状态 |
| 查询失败 | 错误及重试入口 | 重试、返回；不丢失上次清单 |
| 已正式提交 | 当前材料版本，只读 | 地图与清单查看，不可修改 |

本需求不默认把“必须有命中资源”设为申报门槛。建议正式启用后：未使用该功能的旧项目不新增阻断；已开始填写边界的项目，提交时必须完成有效确认且不存在未处理的边界/清单不一致。空清单须有明确空结果确认。是否强制所有新项目填写边界，由厅方年度填报规则另行确认，不能本轮自行设置。

厅方初审只校验资料完整性，不因资源数量自动判达标；专家资料审核、会议和现场评审均可在“申报方提交材料”弹窗中查看同一提交版本的坐标、地图及五列清单，不得直接修改。资源清单供人工按标准核验，不自动转成景观质量得分，不改变厅方复审决定权。

## 7. 数据结构（本地前端已落地，后端待集成）

| 实体 | 核心字段 | 说明 |
|---|---|---|
| ProjectBoundary | projectId、draftVersion、crs、vertices[{order,longitude,latitude}]、geometry、boundaryHash、confirmedAt、confirmedBy | 草稿及确认版本分离；geometry为闭合Polygon；原始输入顺序可追溯。 |
| ResourceQuerySnapshot | queryId、projectId、boundaryHash、classificationVersion、sourceRevision、queriedAt、matchedIds、warnings | 全量匹配与主类筛选分离，保证分类切换不重新丢失资源；后端保存授权范围。 |
| ProjectResourceList | projectId、materialVersionId、queryId、selectedMainClassCodes、boundaryHash、status、revision | 与本次材料版本关联，status区分一致/待更新/正式冻结。 |
| ProjectResourceItem | id、resourceId（补录可空）、sourceType、mainClassCode、subClassCode、basicTypeCode、resourceName、remark、systemWarnings、sourceSnapshot、editedFields | sourceType区分在库匹配、申报补录、人工保留；主库来源与申报修改分离。 |
| ResourceListChange | projectId、itemId、action、before、after、actorId、at、revision | 记录增删改、生成及替换；不改变主库记录。 |

分类代码与名称均需保留版本快照。并发保存采用revision校验，冲突要求刷新核对，不静默覆盖他人修改。当前新增项目可选字段`resourceData`，包含`revision/started/draftRows/confirmed/items/audit/snapshots`；旧项目不强制迁移。`confirmed`记录几何、坐标系、边界哈希、查询编号及时间、主库/分类版本、匹配ID、主类选择、告警及空清单确认。`snapshots`按`materialVersion`留存资源材料冻结副本，补证生成新版本。

## 9. 验收用例

## 10. 开发顺序与待确认项

前端实施已完成：坐标校验、动态地图、主类筛选、五列清单及增删改、重生成差异、草稿、正式资源版本和只读权限。后端开发顺序：P0核定标准分类与坐标系、接入地图与资源主库及授权；P0实现服务端原子提交和不可变快照；P1完成大数据游标、性能指标及协作冲突服务。当前本地演示不改变既有后端待集成清单。
