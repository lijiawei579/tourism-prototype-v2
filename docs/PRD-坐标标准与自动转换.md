# V2补充PRD：坐标标准与自动转换

日期：2026年11月10日；适用版本：V2.16。

## 1. 范围与入口

统一新增/编辑申报资源弹窗、第三个Tab“景区旅游资源概述”的边界点，以及保留但本期隐藏的度假区经度/纬度字段。不修改V1、审批节点、评分及已有正式材料快照。

## 2. 输入与交互

1. 默认选择CGCS2000（2000国家大地坐标系，EPSG:4490）。支持选择WGS84（EPSG:4326）、GCJ-02（高德/腾讯）、BD-09（百度）。同一组边界点使用一个来源标准。
2. 默认采用度分秒分栏录入：经度选择东经/西经，纬度选择北纬/南纬，分别填写度、分、秒。度、分须为非负整数，秒允许最多6位小数，分和秒均为0至小于60。经度最大180度、纬度最大90度，达到上限时分、秒必须为0。方向决定正负，不在度数中输入负号。
3. 可切换为十进制度：经度−180至180，纬度−90至90，最多8位小数。两种方式按同一来源坐标标准互换，保留有效位置；输入无效时阻止切换并定位问题部分，不丢失未完成输入。不解析自由格式度分秒字符串，不自动交换经纬度。
4. 资源弹窗经纬度为必填，演示预填可修改。修改数值或标准后立即显示CGCS2000转换结果；保存错误定位到经/纬度内具体的度、分或秒框，保留其他内容。取消不写入申报副本。
5. 切换来源标准不改输入数值，仅改变其解释方式，提示用户核对来源。再次编辑恢复原始标准、录入方式和原始度分秒，避免重复转换。
6. 边界先将度分秒换算为来源标准的十进制度，再转换坐标标准，校验重复点、零面积、自交等几何规则，最后打开CGCS2000地图预览并按同标准查询资源。取消不覆盖上次确认结果，恢复边界时同时恢复原始标准、录入方式与坐标。
7. 通用经纬度字段保留原有选填属性；两个坐标完全为空可暂存/提交，填写其中一框后必须补齐有效坐标。格式错误沿用“第一个待处理项”定位，跨Tab时定位到可见的具体度/分/秒框。
8. 只读材料可展示CGCS2000的度分秒，不开放标准选择与编辑。正式提交冻结原始输入、转换结果和资源副本；补证新版本不覆盖旧材料。

## 3. 转换口径及精度

| 来源 | 原型处理 | 保存口径 |
|---|---|---|
| CGCS2000 | 校验后原值保存，不做偏移 | EPSG:4490；identity |
| WGS84 | 数值近似对齐CGCS2000参考框架 | 标记approximate=true |
| GCJ-02 | 迭代反解地图偏移，再近似对齐CGCS2000 | 标记approximate=true |
| BD-09 | 去百度偏移、反解GCJ-02，再近似对齐CGCS2000 | 标记approximate=true |

所有非CGCS2000输入均明确显示“近似转换，用于原型演示；精确成果需测绘转换参数”。8位小数是输入/存储精度，不代表测绘精度。当前没有坐标历元、区域实测转换参数或测绘服务，不宣称完成高精度国家大地坐标转换。正式接入时由服务端复核来源标准、范围、参数及转换精度，并采用与主库一致的空间参考。

## 4. 数据结构

| 对象 | 新增/调整字段 | 说明 |
|---|---|---|
| 资源申报副本 | coordinateInput.sourceCrs、sourceValues | 原始标准和经纬度字符串；不改资源主库 |
| 资源/通用坐标输入 | format、dmsValues | format为dms或decimal；dmsValues每轴保留direction、degree、minute、second字符串，原始填写不丢失 |
| 资源申报副本 | geometry、crs | Point坐标统一保存为CGCS2000，crs=EPSG:4490 |
| 资源申报副本 | coordinateConversion | coordinates、crs、sourceCrs、sourceValues、method、approximate、algorithmVersion |
| 边界草稿 | draftCrs、draftRows | 原始标准和每行原始经纬度；旧数据默认CGCS2000 |
| 边界草稿及快照 | draftFormat、draftDmsRows | 全边界统一录入方式；按行、按经纬轴保留方向及度分秒，包括尚未填完的草稿 |
| 已确认边界 | vertices、geometry、coordinateInput、coordinateConversion | 规范坐标、来源标准/原始行、目标标准及近似标记；边界版本根据规范坐标计算 |
| 通用经纬度表单 | coordinateData.input、normalized | 原始输入独立保留；values.longitude/latitude保存转换结果；无效时清空旧规范坐标，防止误存旧值 |
| 正式材料快照 | draftCrs及上述输入/转换结果 | 随材料版本冻结，保留历次输入及转换记录 |

已确认边界coordinateInput同时保存format与dmsRows；draftRows/sourceValues为来源标准下的十进制度数值字符串，最终geometry仍统一按EPSG:4490保存。旧数据不批量改写：没有录入方式时以原十进制度生成度分秒视图，编辑保存后留存新的原始格式。

仍使用浏览器本地存储，不新增虚构的在线接口。生产接口须同时接收原始坐标与标准、服务端转换后的几何和转换元数据；不可只信任客户端计算结果。

## 5. 验收

- 四种标准均可在资源弹窗、边界及通用坐标字段选择；默认CGCS2000。
- 三类入口默认显示度分秒并可切换十进制度；东/西经、南/北纬及接近零度的负坐标可正确转换；秒的小数与59分59秒进位回显正确。
- 分或秒为60、负度数、超限度数、上限处非零分秒、缺少任一必填部分均被阻止，并定位具体部分；无效输入不能通过切换方式绕过。
- 使用已知GCJ-02/BD-09点转换后与对应基准坐标在演示算法容差内一致；WGS84明确标记近似。
- 原始坐标及来源标准可在编辑/重新加载时恢复，规范坐标不被重复反解。
- 无效范围、缺失一轴、过多小数位、非法标准均不能保存有效坐标；提示并定位错误。
- 边界使用转换后的几何查询，确认后不显示待更新；放弃修改恢复标准与原坐标；旧默认边界仍得到原资源数。
- 取消、存储失败、权限不足不改旧副本；正式材料保持只读，资源主库和V1不改变。

## 6. 优先级

P0：统一入口、来源选择、数值校验、标准化保存、原始数据留存、提交冻结和只读展示。

后续集成：服务端测绘参数/坐标转换服务、真实GIS底图与空间库。保持既有后端待集成范围，不新增本期集成承诺。
